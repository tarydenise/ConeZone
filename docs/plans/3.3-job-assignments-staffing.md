## 1. Problem Statement

Jobs can be created, but there is no way to say who is working them. Dispatchers cannot see which jobs are understaffed, field workers cannot see where they are supposed to be, and the job message threads and check-in have no list of crew members to rely on. Fixing this lets a dispatcher staff a job in one place and lets every worker see only their own jobs.

## 2. Goals

- Dispatchers and Admins can assign and remove Field Workers and Supervisors on a job.
- One assigned user can be marked as the job supervisor.
- Every job shows "N of M" staffed, and its status switches between Open and Staffed automatically.
- Workers and Supervisors see only their own jobs in a My Jobs view.
- Assignments become the single source of truth for who belongs to a job (used later by messaging and check-in).

## 3. Non-Goals

- Warning about overlapping jobs when assigning a worker (additional feature 4.4).
- Notifications when someone is assigned, moved, or removed (additional feature 4.2).
- A drag-and-drop crew board or calendar assignment.
- Workers declining, requesting swaps, or signing themselves up for jobs.
- Assigning Dispatchers or Admins to jobs.
- Check-in/out and job messaging. Each has its own plan and only reads assignments from this feature.
- Bulk assignment, job templates, or copying a crew to another job.

## 4. Personas & User Stories

- **As a Dispatcher**, I want to assign workers to a job and see "3 of 4" so that I can fix understaffed jobs before the day starts.
- **As a Dispatcher**, I want to mark one assigned person as the job supervisor so that everyone knows who runs the site.
- **As a Supervisor**, I want to see my assigned jobs and my crew so that I know who to expect.
- **As a Field Worker**, I want a My Jobs list of only my jobs so that I can quickly find where I am working tomorrow.
- **As an Admin**, I want the same assignment powers as a Dispatcher so that I can cover for them.
- Parent and self-learner personas: N/A (not relevant to this app).

## 5. Functional Requirements

- **FR-1.** The system MUST let a Dispatcher or Admin assign a user to a job. Only active users whose role is Field Worker or Supervisor can be assigned.
- **FR-2.** The system MUST NOT allow the same user to be assigned to the same job twice.
- **FR-3.** The system MUST NOT allow an assignment when the number of assigned users already equals the job's workers needed.
- **FR-4.** The system MUST NOT allow assignments to be added, changed, or removed on a job whose status is Completed or Cancelled.
- **FR-5.** The system MUST allow at most one assignment per job to be flagged as job supervisor. Flagging a new one clears the previous flag.
- **FR-6.** The system MUST only allow users whose account role is Supervisor to be flagged as job supervisor.
- **FR-7.** The system MUST let a Dispatcher or Admin remove an assignment. If the removed user was the job supervisor, the job has no supervisor until another is flagged.
- **FR-8.** The system MUST calculate staffed count as the number of assignments on the job and show it as "N of M" (M = workers needed).
- **FR-9.** The system MUST set a job's status to Staffed when its status is Open and N equals M, and back to Open when its status is Staffed and N is less than M. It MUST NOT change a job whose status is In Progress, Completed, or Cancelled.
- **FR-10.** The system MUST recalculate the status whenever an assignment is added or removed or a job's workers needed changes.
- **FR-11.** The system MUST reject lowering a job's workers needed below its current assigned count, and tell the user to remove crew first.
- **FR-12.** The system MUST provide a My Jobs list containing only jobs the current user is assigned to, sorted by date and start time (earliest first). A job counts as past once its end time has passed, so an overnight job that started yesterday evening stays visible until it ends. Past jobs are hidden. Cancelled jobs stay visible with a Cancelled label.
- **FR-13.** The system MUST let an assigned Field Worker or Supervisor read the crew list of their own jobs, and MUST NOT let them read the crew list of any other job.
- **FR-14.** The system MUST delete a job's assignments when the job is deleted.
- **FR-15.** The system SHOULD show deactivated users already on a job as "(inactive)". They still count toward N until a Dispatcher removes them.
- **FR-16.** The system SHOULD show the job supervisor first in the crew list, labeled "Supervisor".
- **FR-17.** The system MAY let the Assign dialog search users by name.
- **FR-18.** The system MUST allow assignments to be added or removed on an In Progress job (for late call-outs), subject to FR-2 and FR-3.
- **FR-19.** The system MUST clear the job supervisor flag on a user's assignments when an Admin changes that user's role away from Supervisor. The user stays on the crew.

## 6. Non-Functional Requirements

- **Performance** — Target (a goal to check, not a hard limit): Job Board and My Jobs lists, including staffed counts, load in under 500 ms (p95) with 500 jobs and 50 users in the database.
- **Security** — Every endpoint checks the user's role on the server, not only in the UI. A user requesting a job they are not assigned to gets a not-found or forbidden response and no data. The user id in a request is validated against existing, active users.
- **Privacy & Compliance** — The crew list shows name and role only. Phone numbers are not shown (see Open Questions).
- **Accessibility** — WCAG 2.1 AA for all new UI. The Assign dialog traps focus, can be closed with Escape, and every control has a visible label. Status is never shown by color alone.
- **Scalability** — N/A (prototype for one company).
- **Reliability** — Adding an assignment and recalculating the job status happen together, so two dispatchers assigning at the same time cannot push a job past its workers needed.
- **Observability** — Log each assignment create, change, and delete with actor id, job id, and user id.
- **Maintainability** — Staffing count and status rules live in one place and are called from both the assignment and job edit flows.
- **Internationalization** — N/A for MVP (English only). UI strings are kept together to make later translation easier.
- **Backward compatibility** — N/A (new feature). The Job list response gains a staffed count field.

## 7. Acceptance Criteria

- **AC-1.** *Given* a Dispatcher viewing an Open job needing 2 workers, *when* they assign an active Field Worker, *then* the job shows "1 of 2" and stays Open.
- **AC-2.** *Given* an Open job with 1 of 2 assigned, *when* the Dispatcher assigns a second worker, *then* the job shows "2 of 2" and its status becomes Staffed.
- **AC-3.** *Given* a Staffed job with 2 of 2 assigned, *when* the Dispatcher removes one worker, *then* the job shows "1 of 2" and its status returns to Open.
- **AC-4.** *Given* a job with 2 of 2 assigned, *when* a Dispatcher tries to assign a third user, *then* the request is rejected with a "job is fully staffed" message and nothing changes.
- **AC-5.** *Given* a user already on a job, *when* a Dispatcher assigns that user again, *then* the request is rejected as a duplicate and the count does not change.
- **AC-6.** *Given* a job with a supervisor already flagged, *when* the Dispatcher flags a different Supervisor, *then* the new one is the job supervisor and the previous one is not.
- **AC-7.** *Given* an assigned user whose role is Field Worker, *when* the Dispatcher tries to flag them as job supervisor, *then* the request is rejected.
- **AC-8.** *Given* a Field Worker assigned to Job A but not Job B, *when* they open My Jobs, *then* only Job A appears, and requesting Job B's crew list returns no data.
- **AC-9.** *Given* a Field Worker, *when* they try to assign or remove a user (including by calling the endpoint directly), *then* the request is rejected as forbidden.
- **AC-10.** *Given* a Cancelled or Completed job, *when* a Dispatcher tries to add or remove an assignment, *then* the request is rejected and the crew is unchanged.
- **AC-11.** *Given* a job with 3 assigned, *when* the Dispatcher edits workers needed to 2, *then* the edit is rejected with a message to remove crew first.
- **AC-12.** *Given* a Staffed job needing 2, *when* the Dispatcher edits workers needed to 3, *then* the job shows "2 of 3" and its status becomes Open.
- **AC-13.** *Given* a job with assignments, *when* the job is deleted, *then* its assignments are also removed and the workers' My Jobs lists no longer show it.
- **AC-14.** *Given* a Field Worker with no assignments, *when* they open My Jobs, *then* they see the "no upcoming jobs" empty state.
- **AC-15.** *Given* an overnight job (9:00 PM to 5:00 AM) that started yesterday, *when* an assigned worker opens My Jobs at 1:00 AM, *then* the job still appears.
- **AC-16.** *Given* a job whose supervisor is Sam, *when* an Admin changes Sam's role to Field Worker, *then* Sam remains on the crew and the job has no supervisor.
- **AC-17.** *Given* an In Progress job with 1 of 2 assigned, *when* a Dispatcher assigns a second worker, *then* the job shows "2 of 2" and its status stays In Progress.
- **AC-18.** *Given* a deactivated user assigned to a job, *when* anyone on the job opens the crew list, *then* the user shows as "(inactive)" and is still counted in N.

## 8. Data Model

**Assignment (new)**

| Field | Type | Notes |
|---|---|---|
| id | identifier | primary key |
| job | reference to Job | required; assignments are deleted when the job is deleted |
| user | reference to User | required |
| is_job_supervisor | boolean | default false |
| checked_in_at | datetime | nullable; used by feature 3.5, included now so the table does not change later |
| checked_out_at | datetime | nullable; used by feature 3.5 |
| created_at / updated_at | datetime | |

- **Constraints:** (job, user) must be unique. At most one assignment per job may have is_job_supervisor = true.
- **Indexes:** by job and by user (for the crew list and My Jobs).
- **Job:** no new stored fields. Staffed count is calculated from assignments, not stored, so it cannot drift out of sync. The existing status values are reused.
- **Migration:** one migration that creates the Assignment table. File naming follows the team's chosen stack, which is not decided yet.
- **Backfill:** none. No assignments exist today. Development seed data: about 10 users across roles and 6 jobs in different staffing states.

## 9. API Surface

All routes require a logged-in user. Paths are illustrative and may change during implementation.

| Method | Path | Purpose | Allowed |
|---|---|---|---|
| GET | `/api/jobs/:id/assignments` | List the crew on a job | Assigned users, Dispatcher, Admin |
| POST | `/api/jobs/:id/assignments` | Assign a user | Dispatcher, Admin |
| PUT | `/api/assignments/:id` | Set or clear the job supervisor flag | Dispatcher, Admin |
| DELETE | `/api/assignments/:id` | Remove a user from a job | Dispatcher, Admin |
| GET | `/api/jobs/mine` | The current user's upcoming jobs | Any logged-in user |

**Changed route:** `GET /api/jobs` and `GET /api/jobs/:id` also return `staffed_count`.

**Request and response shapes (pseudo-TypeScript)**

```
POST /api/jobs/:id/assignments
  body:     { user_id: string, is_job_supervisor?: boolean }
  201:      { assignment: Assignment, job: { id, status, staffed_count, workers_needed } }

PUT /api/assignments/:id
  body:     { is_job_supervisor: boolean }
  200:      { assignment: Assignment }

DELETE /api/assignments/:id
  200:      { job: { id, status, staffed_count, workers_needed } }

GET /api/jobs/:id/assignments
  200:      [{ id, is_job_supervisor, user: { id, name, role, is_active } }]

GET /api/jobs/mine
  200:      [{ ...job fields, staffed_count, my_assignment: { is_job_supervisor } }]

Assignment = { id, job_id, user_id, is_job_supervisor }
```

**Errors:** 400 invalid input (for example, a user id that does not exist, or a non-Supervisor flagged as job supervisor), 401 not logged in, 403 role not allowed, 404 job or assignment not found (also used when a worker asks for a job they are not on), 409 conflict (duplicate assignment, job fully staffed, job Completed or Cancelled).

**Real-time events:** N/A for this plan (additional feature). **Rate limits:** N/A. **Documentation:** each route is added to the README API section.

## 10. UI / UX

**Pages and components**

- **Job Detail, Crew panel (modified):** shows "Crew (N of M)", each member with role, the job supervisor labeled, a Remove button, and + Assign for Dispatchers and Admins.
- **Assign dialog (new):** search box, list of eligible users with checkboxes, a "make supervisor" choice limited to users with the Supervisor role, Cancel and Save.
- **Job Board (modified):** the Staff column shows "N / M" and the status chip.
- **My Jobs (new, mobile first):** Today and Upcoming sections with job cards.

**Key flows**

1. Dispatcher opens a job, selects + Assign, picks users, optionally picks a supervisor, and saves.
2. The crew list and "N of M" update, and the status chip changes if the job became Staffed.
3. Dispatcher removes a crew member, and the count and status update.
4. Worker opens My Jobs, sees assigned jobs, and taps one to open its details.

**States**

- **Empty:** crew list shows "No one assigned yet" (with an Assign button for Dispatchers and Admins). My Jobs shows "You have no upcoming jobs. Check back after dispatch assigns you."
- **Loading:** a simple placeholder while lists load.
- **Error:** inline message when an assignment is rejected (for example, "Job is fully staffed. Increase workers needed to add more." or "That person is already on this job.").
- **Offline:** N/A for MVP (offline support is a stretch feature).

**Responsive:** My Jobs and the Job Detail crew list work at phone width (about 375 px) with large tap targets. The Assign dialog is full screen on a phone.

**Accessibility:** dialog focus is trapped and returned to the Assign button on close. Checkboxes have labels. The supervisor choice is a labeled radio group. Staffing status is text, not just color.

**Copy keys:** `crew.title`, `crew.empty`, `crew.assign`, `crew.fullyStaffed`, `crew.duplicate`, `crew.inactive`, `myjobs.title`, `myjobs.empty`.

## 14. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Two dispatchers assign at the same time and exceed workers needed | M | M | Check the count and write the assignment together in one step; test it |
| Status goes out of sync when workers needed is edited | M | H | One shared staffing rule used by both assignment and job edit; ACs 11 and 12 |
| Role checks only in the UI, so a worker can call an endpoint directly | M | H | Server-side role checks on every route; AC-9 and a role-by-endpoint test matrix |
| A worker sees another worker's job by guessing a job id | L | H | Membership check on every job read; AC-8 |
| Scope creeps into conflict warnings or notifications | H | L | Listed as non-goals; add them only after this plan's ACs pass |

## 15. Rollout Plan

- **Feature flag:** none. This is a core MVP feature in a class project.
- **Sequencing:** schema, then API, then UI. Seed data is added once the API works.
- **Dogfood:** the team uses seed data (about 10 users, 6 jobs) to staff and unstaff jobs as each role.
- **GA criteria:** all acceptance criteria pass and the role-by-endpoint tests pass.
- **Rollback:** revert the feature's pull request. In development, the migration can be undone by dropping the Assignment table.

## 16. Test Plan

- **Unit:** staffing rules (count, Open/Staffed switching, never touching other statuses); supervisor flag rules; eligibility rules (active, role).
- **Integration:** every route for each role (Field Worker, Supervisor, Dispatcher, Admin) with allowed and forbidden results; duplicate, over-assignment, and Completed/Cancelled conflicts; job delete removing assignments; workers needed edits (ACs 11 and 12).
- **End-to-end:** Dispatcher staffs a job and sees it become Staffed; worker logs in on a phone-size screen and sees only their jobs.
- **Security:** a worker calling assign and remove routes directly; a worker requesting a job they are not on; invalid user ids.
- **Accessibility:** automated checker on Job Detail, the Assign dialog, and My Jobs; keyboard-only walk through the dialog.
- **Performance:** load the Job Board and My Jobs with 500 jobs and 50 users and confirm the 500 ms target.
- **Manual exploratory:** two browsers assigning to the same job at once; deactivating an assigned user; resizing to phone width.
